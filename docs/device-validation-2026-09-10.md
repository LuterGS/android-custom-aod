# Galaxy Z TriFold 실기기 검증 — 2026-09-10

## 환경과 방법

- ADB 모델: SM-F968N (`q7mqksx`), Android 16.
- 빌드: `BP4A.251205.006.F968NKSS7BZH3`. One UI 8.5는 사용자 제공 정보.
- 기존 서명 APK v1.2의 데이터를 보존하기 위해 별도 패키지 `dev.lutergs.sgaod.test`를 설치했다.
  기존 앱은 강제 종료했으며 삭제하거나 데이터를 초기화하지 않았다.
- 테스트 패키지에는 합성 알림·미디어 상태만 출력하는 진단 코드를 추가했다.
  별도 테스트 앱으로 실제 NotificationListener/MediaSession 콜백을 발생시켰으며 오디오는 재생하지 않았다.
  테스트 앱과 진단 코드는 배포 소스에 포함하지 않는다.
- 시스템 화면 꺼짐 시간은 기존 600,000ms를 유지했다. 전력·배터리·발열 시뮬레이션은 검사 후 복원했다.

윈도우 밝기 요청값이며 실제 휘도의 선형 백분율을 의미하지 않는다.

## 미해결·미검증

- **하단 스와이프 바:** 사용자가 계속 보인다고 확인했고 시스템 영역의 스크린샷에도 남아 있었다.
  앱은 전체화면과 시스템 바 숨김을 요청했으며 WindowManager의 navigationBars Insets는
  `visible=false`였다. One UI의 실제 표시와 불일치한다. 전체화면 전환 뒤 재요청을 추가했지만
  해결됐다고 판정할 수 없다. 구형 immersive 플래그도 테스트했으나 효과가 없어 배포 코드에는 추가하지 않았다.
  이후 뒤집힘 검사 뒤에는 시계·알림 복귀 후에도 하단 바가 숨겨졌다고 사용자가 확인했다.
  그러나 새 화면 OFF 세션을 시작하자 시스템 영역 스크린샷에 바가 다시 나타나 전체 해결로 판정하지 않는다.
  잠금 전환 후 1초 뒤 숨김을 재요청하는 실험 빌드를 만들었지만 설치 도중 ADB가 offline으로 바뀌었고
  기존 주소 재연결도 거부됐다. 이 실험은 검증되지 않았으며 배포 코드에 추가하지 않았다.
- **물리 1Hz:** 앱의 1Hz 요청은 확인했지만 공개 디스플레이 진단은 내부 화면의 논리 모드와
  앱 프레임레이트 override를 10Hz로 보고했다. 공개 모드 목록의 최저값도 10Hz였다.
  이것으로 물리 LTPO 패널의 실제 주사율을 확정할 수 없으며 **1Hz 보장을 검증하지 못했다.**
- **주머니·뒤집힘:** 근접 화면 소등 WakeLock 지원과 등록은 확인했다. 사용자는 접힌 화면에서는
  가림·뒤집힘 모두 작동하지만 펼친 AOD에서는 둘 다 작동하지 않는다고 보고했다.
  펼친 상태에서 재시도해도 실패했다고 보고했다. 최초 약 4분간의 기록에서는 AOD 세션과 센서 등록은
  유지됐으나 조작 시점이 기록 구간에 포함됐는지 확인하지 못했다. 해당 기록을 센서 고장의 증거로
  사용하지 않는다. 테스트 앱에 최근 센서 변화 64개, Z축 최솟값/최댓값, 뒤집힘 판정 이력을
  보관하는 진단을 추가하여 조작 후에도 조회할 수 있도록 했다. 이 진단은 배포 코드에 포함하지 않는다.
  이 진단을 설치한 후 Z축 최솟값 약 -9.8, `DOWN=true`/`DOWN=false` 전환이 기록됐다.
  같은 시점인 13:24:08에 WindowManager의 화면 유지 WakeLock 해제, 13:24:13에 재획득도 확인했다.
  근접 값은 여전히 far(5)만 기록됐다. 실제 콘텐츠 암전과 패널 OFF는 별도 확인이 필요하며
  전체 성공으로 판정하지 않는다.
  이후 사용자는 진단 빌드에서 뒤집었을 때 시계·알림·하단 바가 모두 사라졌다고 확인했다.
  진단에도 추가 `DOWN=true`/`DOWN=false` 전환이 남았고, 다시 든 뒤 조회에서는
  `sleepReason=NONE`, `activityVisible=true`, 밝기 요청 0.7, 화면 유지 플래그 재설정을 확인했다.
  사용자도 다시 들었을 때 시계·알림이 보이고 하단 바만 없다고 확인하여 뒤집힘 암전·복귀를 확인했다.
  이 결과는 뒤집힘 암전 확인이며 패널의 실제 OFF 또는 손바닥 가림 성공을 의미하지 않는다.
- **접힘/펼침:** 커버와 내부 패널은 ADB에서 식별했으나 AOD 표시 중 전환은 아직 검증하지 않았다.
- **소비전력:** 장시간 대기·시스템 AOD와의 배터리 비교는 하지 않았다. 프레임 감소만으로
  동일한 소비전력을 보장하지 않는다. 뒤집힘 등 근접 이외의 암전은 화면 유지 플래그를 해제하는
  방식이므로 시스템 화면 꺼짐 시간까지 패널 OFF가 지연될 수 있다.

통화, 재부팅, DeX, 장시간 센서 복귀 및 모든 알림 공개 설정 조합에 대한 실기기 검증도 남아 있다.

합성 알림·미디어 테스트 서비스는 종료했고, 새 AOD 세션에서 테스트 알림 목록이 비었으며
합성 곡도 제거됐음을 확인했다. 연결 종료 전 마지막 확인 상태는 별도 테스트 AOD 활성화 상태다.

## 센서 위치 참고

[삼성 SM-F968B/DS Android 16 설명서](https://downloadcenter.samsung.com/content/UM/202512/20251219110356362/SM-F968B_DS_UG_ASIA_16_Eng_Rev.1.0_251128.pdf)
4쪽은 내부 화면에 조도 센서, 5쪽은 커버 화면에 근접/조도 센서를 표시한다.
이는 같은 모델 계열의 해외판 설명서이며 해당 한국판 펌웨어의 센서 API 동작 보장은 아니다.
내부 화면 위쪽을 가리는 조작이 커버 쪽 근접 센서에 전달되지 않을 가능성을 설명하지만,
내부 화면의 가림 감지를 해결했다고 볼 수 없다. 단순히 어두움으로 판정하는 조도 센서 대체는
어두운 방에서도 AOD를 끄게 될 수 있으므로 동일한 동작으로 취급하지 않는다.
