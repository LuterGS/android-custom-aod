# Galaxy Z TriFold 실기기 검증 — 2026-09-10

## 환경과 방법

- ADB 모델: SM-F968N (`q7mqksx`), Android 16.
- 빌드: `BP4A.251205.006.F968NKSS7BZH3`. One UI 8.5는 사용자 제공 정보.
- 기존 서명 APK v1.2의 데이터를 보존하기 위해 별도 패키지 `dev.lutergs.sgaod.test`를 설치했다.
  기존 앱은 강제 종료했으며 삭제하거나 데이터를 초기화하지 않았다.
- 테스트 패키지에는 합성 알림·미디어 상태만 출력하는 진단 코드를 추가했다.
  별도 테스트 앱으로 실제 NotificationListener/MediaSession 콜백을 발생시켰으며 오디오는 재생하지 않았다.
  테스트 앱과 진단 코드는 배포 소스에 포함하지 않는다.
- 시스템 화면 꺼짐 시간은 기존 600,000ms를 유지했다. 전력·배터리·발열 시뮬레이션은 검사 후 복원했다.

## 미해결·미검증

- **하단 스와이프 바:** 사용자가 계속 보인다고 확인했고 시스템 영역의 스크린샷에도 남아 있었다.
  앱은 전체화면과 시스템 바 숨김을 요청했으며 WindowManager의 navigationBars Insets는
  `visible=false`였다. One UI의 실제 표시와 불일치한다. 전체화면 전환 뒤 재요청을 추가했지만
  해결됐다고 판정할 수 없다. 구형 immersive 플래그도 테스트했으나 효과가 없어 배포 코드에는 추가하지 않았다.
  이후 뒤집힘 검사 뒤에는 시계·알림 복귀 후에도 하단 바가 숨겨졌다고 사용자가 확인했다.
  그러나 새 화면 OFF 세션을 시작하자 시스템 영역 스크린샷에 바가 다시 나타나 전체 해결로 판정하지 않는다.
  잠금 전환 후 1초 뒤 숨김을 재요청하는 실험 빌드를 만들었지만 설치 도중 ADB가 offline으로 바뀌었고
  기존 주소 재연결도 거부됐다. 이 실험은 검증되지 않았으며 배포 코드에 추가하지 않았다.
- **물리 1Hz:** 앱의 1Hz 요청은 확인했지만 공개 디스플레이 진단은 내부 화면의 논리 모드와
  앱 프레임레이트 override를 10Hz로 보고했다. 공개 모드 목록의 최저값도 10Hz였다.
  이것으로 물리 LTPO 패널의 실제 주사율을 확정할 수 없으며 **1Hz 보장을 검증하지 못했다.**
- **주머니·뒤집힘:** 근접 화면 소등 WakeLock 지원과 등록은 확인했다. 사용자는 접힌 화면에서는
  가림·뒤집힘 모두 작동하지만 펼친 AOD에서는 둘 다 작동하지 않는다고 보고했다.
  펼친 상태에서 재시도해도 실패했다고 보고했다. 최초 약 4분간의 기록에서는 AOD 세션과 센서 등록은
  유지됐으나 조작 시점이 기록 구간에 포함됐는지 확인하지 못했다. 해당 기록을 센서 고장의 증거로
  사용하지 않는다. 테스트 앱에 최근 센서 변화 64개, Z축 최솟값/최댓값, 뒤집힘 판정 이력을
  보관하는 진단을 추가하여 조작 후에도 조회할 수 있도록 했다. 이 진단은 배포 코드에 포함하지 않는다.
  이 진단을 설치한 후 Z축 최솟값 약 -9.8, `DOWN=true`/`DOWN=false` 전환이 기록됐다.
  같은 시점인 13:24:08에 WindowManager의 화면 유지 WakeLock 해제, 13:24:13에 재획득도 확인했다.
  근접 값은 여전히 far(5)만 기록됐다. 실제 콘텐츠 암전과 패널 OFF는 별도 확인이 필요하며
  전체 성공으로 판정하지 않는다.
  이후 사용자는 진단 빌드에서 뒤집었을 때 시계·알림·하단 바가 모두 사라졌다고 확인했다.
  진단에도 추가 `DOWN=true`/`DOWN=false` 전환이 남았고, 다시 든 뒤 조회에서는
  `sleepReason=NONE`, `activityVisible=true`, 밝기 요청 0.7, 화면 유지 플래그 재설정을 확인했다.
  사용자도 다시 들었을 때 시계·알림이 보이고 하단 바만 없다고 확인하여 뒤집힘 암전·복귀를 확인했다.
  이 결과는 뒤집힘 암전 확인이며 패널의 실제 OFF 또는 손바닥 가림 성공을 의미하지 않는다.
- **접힘/펼침:** 커버와 내부 패널은 ADB에서 식별했으나 AOD 표시 중 전환은 아직 검증하지 않았다.
- **소비전력:** 장시간 대기·시스템 AOD와의 배터리 비교는 하지 않았다. 프레임 감소만으로
  동일한 소비전력을 보장하지 않는다. 뒤집힘 등 근접 이외의 암전은 화면 유지 플래그를 해제하는
  방식이므로 시스템 화면 꺼짐 시간까지 패널 OFF가 지연될 수 있다.

통화, 재부팅, DeX, 장시간 센서 복귀 및 모든 알림 공개 설정 조합에 대한 실기기 검증도 남아 있다.

합성 알림·미디어 테스트 서비스는 종료했고, 새 AOD 세션에서 테스트 알림 목록이 비었으며
합성 곡도 제거됐음을 확인했다. 연결 종료 전 마지막 확인 상태는 별도 테스트 AOD 활성화 상태다.

## 재연결 후 지연·자동 밝기·터치 추가 검증

같은 기기에 UI·이름 조회·자동 밝기·터치 개선이 포함된 PR 빌드를 설치한 뒤,
지연 개선 전후를 비교했다. 테스트 패키지에만 단조 시계 기반 이벤트·버퍼 제출 시각을
최근 128개까지 보관했다. 알림 원문이나 앱 이름은 기록하지 않고 조회 성공 개수만 확인했다.
배포 소스에는 이 계측 코드가 없다.

| 구간 | 변경 전 | 변경 후 |
|---|---|---|
| 화면 OFF 수신 후 세션 시작 → 첫 콘텐츠 버퍼 제출, 3회 | 1,124 / 1,097 / 1,068ms | 484 / 493 / 463ms |
| 짧은 절전 모드 암전 해제 판정 → 콘텐츠 버퍼 제출, 1회 | 605ms | 73ms |
| 실제 뒤집힘 센서 해제 감지 → 콘텐츠 버퍼 제출, 1회 | 미측정 | 228ms (해제 판정까지 202ms, 이후 26ms) |
| 커버 화면 근접 센서 가림 해제 감지 → 콘텐츠 버퍼 제출, 1회 | 미측정 | 270ms (해제 판정까지 200ms, 이후 70ms) |

잠금 시작 구간의 중앙값은 1,097ms에서 484ms로 약 56% 감소했다. 절전 모드 비교는 약 250ms
동안 시스템 절전을 켰다가 끈 조작이다. 모든 수치는 앱 내부 이벤트부터 Surface 버퍼 제출까지이며,
손을 움직이기 시작한 시점이나 실제 패널 발광 시점을 측정한 값이 아니다. 센서 표본 도착 전 지연,
기기 수면·부하 및 제조사 전력 정책에 따른 지연까지 보장하지 않는다.

변경 사항은 센서 초기값 수신 시 즉시 진행(무응답 시 최대 1초 대기), 가림·뒤집힘 해제 안정화
1,200ms → 200ms, 암전 버퍼를 콘텐츠 프레임 제한의 기준 시각에서 제외한 것이다.
뒤집힘 진입 700ms, 근접 진입 즉시 차단, 콘텐츠 최대 1fps와 기존 센서 요청 속도는 유지했다.
폴링이나 CPU 유지 WakeLock을 추가하지 않았다.

- 사용자가 화면을 뒤집었다 들기, 접힌 커버 센서를 가리고 두 번 탭한 뒤 떼기를 수행하고
  “테스트해봤고, 잘 돼”라고 확인했다. 기록에도 `FACE_DOWN`·`COVERED` 진입과 `NONE` 복귀가 남았다.
- 활성 알림 50개 모두 앱 이름을 조회했고 패키지명 그대로 표시되는 항목과 대체 이름은 0개였다.
  모든 앱·업무 프로필 조합의 검증을 의미하지 않는다.
- 시스템 자동 밝기 켬 → Window 밝기 -1(시스템 위임), 끔 → 저장된 수동 밝기 0.7을 확인했다.
  주변 조도에 따른 실제 휘도 곡선을 측정한 것은 아니다.
- 절전 모드 암전 시 Window 밝기 0, 화면 유지 플래그 해제를 확인했다. ADB로 두 번 탭을 주입한
  뒤에도 세션이 유지되고 암전 중 제출 프레임 수는 40으로 유지됐다. 절전 해제 시 정상 복귀했다.
- 검사 후 시스템 자동 밝기 설정은 기존 수동 모드, 절전 모드는 기존 꺼짐 상태로 복원했다.
- 최종 소스의 Debug/Release 빌드, JUnit 48개, Lint 오류 0개를 확인했다. 기존 버전 관련 경고 3개 유지.

이 추가 결과가 펼친 내부 화면의 손바닥 가림, 새 잠금의 하단 바, 물리 패널 1Hz 및 장시간
소비전력의 기존 미해결·미검증 상태를 바꾸지는 않는다.

## 충전 표시·사용자 설정 추가 검증

이후 빌드에서 충전 아이콘·예상 시간, 개별 글자 크기·전체 배율, 테마, 우선 앱과 표시 개수 설정을 추가했다.

- 같은 기기에서 미연결 시 `plugged=0`, `status=3`, `hv_charger=false`를 확인했다.
  사용자가 고속 충전기를 연결하자 `plugged=1`, `status=2`, `hv_charger=true`로 바뀌었다.
  최대 충전 전류·전압은 모두 0으로 보고되어 이 기기에서는 삼성의 선택적 고속 플래그를 사용했다.
- 공개 충전 예상 시간 API가 795,000ms를 반환했고, 변경 빌드에서도 충전 86%, 고속 true,
  남은 시간 726,000ms로 수신했다. 사용자가 배터리 안 번개 두 개와 ‘완충까지 약 ○분’ 표시를 확인했다.
- 테스트 전용 코드로 일반·고속·일시정지·분리 Intent를 `BatteryReader`에 전달하여 모델 전환을 확인했다.
  일반/무선 충전기의 물리 연결 또는 배터리 보호로 실제 충전이 멈추는 상황을 재현한 것은 아니다.
- 별도의 임시 설정 파일로 테마·개별 크기·전체 배율·우선 앱·표시 개수의 저장/새 저장소 재조회를 확인했다.
- 기기의 실제 Canvas와 렌더러로 7가지 합성 화면을 그렸다. 커버 기본/최대 크기·15행,
  내부 사용자 설정, 가로 최대 크기·15행, 우선 앱만 표시, 일반 충전과 방전 화면을 검토했다.
  전체가 화면 안에 배치되고 번개 수·테마 색상·흰색 방전 배터리가 구분됐다.
  [사용자 설정 예시](images/aod-customization.png)는 개인 알림이 없는 합성 데이터 렌더링이며
  실제 잠금화면 스크린샷이나 물리 패널의 밝기 측정이 아니다.
- 사용자가 설정에서 선택한 우선 앱을 저장한 상태에서 UI를 검사했다. 우선 개수 4·일반 개수 7,
  시계/날짜/오전·오후/전체 배율 각각 159%로 슬라이더 조작 후 저장값을 확인했다.
  아이스 블루 프리셋과 직접 입력 `#12AB34`의 저장, 미리보기 진입·내용/우선/충전 예시 전환도 확인했다.
  검사 후 변경한 7개 표시 설정은 원래 값으로 복원하고 사용자가 선택한 우선 앱과 다른 설정은 유지했다.
- Debug/Release 빌드, JUnit 61개, Lint 오류 0개를 확인했다. 기존 SDK·빌드 도구 경고 3개 유지.

## 상단 배치·배율 유지 후속 변경

사용자 요청에 따라 화면 크기에 맞춘 자동 축소를 제거했다. 설정한 배율을 그대로 사용하며,
카메라 컷아웃 안전 영역 아래 24dp에서 시작한다. 하단으로 넘치는 내용은 Surface 경계에서 잘린다.
오전/오후와 배터리·완충 예상 시간을 같은 줄에 배치하여 세로 공간을 줄였다.
동일 기기에 수정 빌드를 설치하고 실제 렌더러의 합성 기본/사용자 설정/최대 배율 화면에서
상단 배치·한 줄 상태 표시·확대 유지 및 넘침 잘림을 확인했다. 큰 배율은 좌우 넘침도 잘린다.
Debug/Release 빌드, 기존 JUnit 61개와 Lint 오류 0개를 재확인했다.

## 센서 위치 참고

[삼성 SM-F968B/DS Android 16 설명서](https://downloadcenter.samsung.com/content/UM/202512/20251219110356362/SM-F968B_DS_UG_ASIA_16_Eng_Rev.1.0_251128.pdf)
4쪽은 내부 화면에 조도 센서, 5쪽은 커버 화면에 근접/조도 센서를 표시한다.
이는 같은 모델 계열의 해외판 설명서이며 해당 한국판 펌웨어의 센서 API 동작 보장은 아니다.
내부 화면 위쪽을 가리는 조작이 커버 쪽 근접 센서에 전달되지 않을 가능성을 설명하지만,
내부 화면의 가림 감지를 해결했다고 볼 수 없다. 단순히 어두움으로 판정하는 조도 센서 대체는
어두운 방에서도 AOD를 끄게 될 수 있으므로 동일한 동작으로 취급하지 않는다.
