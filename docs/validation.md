# 검증 기록과 TriFold 실기기 절차

## 자동 검증

2026-09-10, Linux ARM64 빌드 서버에서:

- Debug APK 빌드
- Release APK 빌드(R8·리소스 축소, 서명 환경변수 없으면 unsigned)
- JUnit 61개: 절전 정책 18개, 프레임 간격 7개, 센서 초기 준비 3개, 알림 공개 정책 8개,
  앱 레이블 4개, 자동 밝기·암전 중 터치·번인 이동 8개,
  커스터마이즈·우선 알림 8개, 충전 표시 5개
- Android Lint: 오류 없음. Android 16 targetSdk 유지 및 기존 AGP/Gradle 버전 관련 경고는 유지

이 서버에서는 SDK의 x86-64 AAPT2를 Debian x86-64 컨테이너로 실행했다.
Gradle에는 로컬 전용 `-Pandroid.aapt2FromMavenOverride=/tmp/sgaod-build-tools/bin/aapt2`를 전달했다.
이 경로는 저장소 설정에 포함하지 않는다. 일반 x86-64 Linux CI에서는 표준 Gradle 명령을 사용한다.

**ADB 연결 후 설치·표시·알림·미디어·절전 조건을 추가 검증했다.**
결과와 미해결 항목은 [2026-09-10 실기기 기록](device-validation-2026-09-10.md)에 정리했다.
뒤집힘 암전·복귀는 사용자가 확인했다. 펼친 화면의 손바닥 가림과 최초 잠금의 하단 바는 미해결이며,
접힘 전환·장시간 소비전력·물리 1Hz는 아직 검증하지 못했다.
자동 테스트는 정책의 결정과 콘텐츠 프레임 간격을 검증한다. Android 콜백 순서·제조사 하드웨어를
에뮬레이션한 통합 테스트가 아니며, 아래 실기기 검증을 대체하지 않는다.

### 연결 해제 후 UI·표시 보강

새 AOD 렌더러, 앱 내 미리보기, 앱 이름 조회 개선, 시스템 자동 밝기 연동,
암전 터치 무시 및 픽셀 이동 검증을 반영한 뒤 위 4개 Gradle 작업을 다시 통과했다.
Lint 오류 0개, 기존 SDK/빌드 도구 버전 관련 경고 3개다.
디자인 구성 시안을 검토했으며 실제 Android 렌더러와 같은 코드를 쓰는 미리보기를 앱에 추가했다.
연결 해제 중에는 실기기 검증을 하지 않았다. 이후 재연결하여 새 빌드를 설치하고 알림 50개의
이름 조회, 시스템 자동 밝기 전환, 절전 모드 암전 중 주입한 터치 무시를 확인했다.
잠금·복귀 지연 개선 전후의 동일 기기 측정은 실기기 기록의 추가 검증 절에 구분해 정리했다.
업무 프로필 전체와 주변 조도에 따른 실제 패널 휘도 변화는 검증하지 않았다.

### 충전 표시·커스터마이즈 복원

추가한 단위 검사는 충전 상태별 번개 수, 고속 정보 부재·임계값, 남은 시간 올림·만료·오래된 값,
우선/일반 영역의 독립 개수·0개 숨김·제외 앱 우선 적용·공개 범위 유지·삭제 반영·폭주 시 보관 한도,
저장값 범위 정규화를 검증한다.

재연결한 TriFold에서 고속 충전기 연결 후 `hv_charger=true`, 충전 중 상태와 공개 API의
완충 예상 시간 795,000ms(올림 14분)를 확인했다. 사용자가 번개 두 개와 예상 시간 표시를 확인했다.
격리된 테스트 설정 파일의 저장·재조회, 합성 Intent로 일반/고속/일시정지/분리 전환도 검증했다.
기기에서 실제 `AodRenderer`로 예시 데이터를 Bitmap에 그려 커버·내부·가로 화면과 최대 크기·15행을
검토했다. [예시 렌더링](images/aod-customization.png)은 이 방식의 결과이며 실제 알림 스크린샷이 아니다.
실제 설정 UI에서 6개 슬라이더, 프리셋·직접 색상 입력, 미리보기의 내용·우선·충전 전환도 확인했다.
검사 후 테스트로 바꾼 표시 설정은 복원했다.
일반/무선 충전기의 실제 연결 및 배터리 보호 목표에 도달할 때의 동작은 아직 미검증이다.

## 기기와 준비

대상: Galaxy Z TriFold / Android 16 / One UI 8.5 (사용자 제공).
펌웨어 빌드 번호, 접힌 상태/펼친 상태, 패널 밝기와 시스템 화면 꺼짐 시간, 센서 목록을 기록한다.

1. 동일 서명의 APK를 설치하고 v2의 권한·AOD를 켠다. v1 설정은 새 설정에 자동 적용되지 않는다.
2. 시스템 AOD는 꺼서 두 AOD의 충돌을 피한다.
3. 알림 접근, 오버레이, 전화 상태(통화 검사 시) 권한을 확인한다.
4. 잠금은 화면이 꺼진 즉시 적용되도록 한다. 잠금 유예 중에는 폴링하며 기다리지 않으므로 AOD가 생략될 수 있다.
5. 개발자 옵션의 화면 항상 켜짐·주사율 표시·레이아웃/GPU 오버레이와 화면 녹화를 끈다.
   측정 도구 자체의 오버레이/녹화가 주사율에 영향을 줄 수 있다.

## 기능·상태 전환

| 시나리오 | 확인할 결과 |
|---|---|
| 접힌 커버 화면에서 화면 끄기 | 검정 배경의 시계·날짜·배터리. 잠금화면 정보 노출 정책 유지 |
| 펼친 내부 화면에서 화면 끄기 | 콘텐츠가 화면 밖으로 잘리지 않고 작은 영역에 표시 |
| AOD 중 접기/펼치기/회전 | Surface 크기 변경·재생성 후 재배치. 중복 Activity/FGS 없음 |
| DeX 사용 중 화면 잠금 | 기본 디스플레이에 표시하며 외부 모니터를 AOD로 덮지 않음. 전체화면 요청 거부도 크래시 없음 |
| 일반 알림 게시/갱신/제거, 대화 2개, 그룹 요약 | 최신 개별 알림, 요약 중복 없음, 설정한 행 수와 추가 개수 |
| 비공개/secret/채널 override/전역 숨김 | 숨겨진 내용이 AOD에 나타나지 않음. 설정 변경·리스너 재연결 뒤에도 유지 |
| 음악 재생/일시정지/곡 변경/앱 종료 | 표시 상태 갱신, 진행률·재생 조작 없음. 숨긴 뒤 다시 표시해도 최신 상태 |
| 유선/무선 연결·분리, 완충 | 번개 수·흰색 방전·완료 상태 갱신. 충전 중 제공된 예상 시간만 표시 |
| 충전 일시정지·배터리 보호·예상 시간 미제공 | 번개·오래된 시간 제거, 상태에 맞는 대체 문구 |
| 우선 앱 선택·제외 앱 중복·일반 개수 0 | 별도 우선 영역, 제외 앱 미노출, 우선 앱만 표시 |
| 글자 크기·배율 50/200% 및 우선 5·일반 10개 | 화면 밖 잘림 없음, 글자 크기와 간격 재계산, 분 단위 물리 픽셀 이동 유지 |
| 색상 프리셋·6자리 직접 입력·앱 재시작 | 선택값 저장, 미리보기·AOD 반영, 잘못된 색상 입력은 오류 안내 |
| AOD에서 두 번 탭·볼륨 키 | 세션 종료. 사용자가 새로 화면을 끄기 전 재실행 없음 |
| AOD에서 전원 버튼·잠금 해제 | 시스템 조작 우선, 화면을 다시 강제 점등하는 루프 없음 |
| 전화 수신/통화(권한 허용) | AOD 종료. 통화 앱이 표시됨 |
| AOD 켜기 전부터 주머니에 넣기 | 초기 센서 확인 후 가려진 상태에서 화면을 켜지 않음 |
| 표시 중 주머니/가방, 손으로 센서 가림 | 즉시 검정 전환. 지원 시 근접 소등 API로 패널 OFF |
| 꺼낸 뒤 센서 경계에 손 흔들기 | 가림 해제 200ms 안정화 후 복귀. 반복 점멸 없음 |
| 화면을 아래로 놓았다가 뒤집기 | 안정된 방향 판정 후 암전, 다른 차단 조건이 없으면 복귀 |
| 근접/방향 센서 미지원 | 크래시 없음. 해당 감지는 동작하지 않으며 진단 화면에 부재 표시 |
| 절전 모드·저전력·발열·취침 시간 | 해당 조건 동안 암전. 가림 해제만으로 보호 조건을 무시하지 않음 |
| 30분 표시 제한 | 검정 전환·화면 유지 해제. 시스템 수면 이후 프레임/미디어 반복 작업 없음 |
| 가린 상태에서 AOD 끄기 | 근접 WakeLock·센서 해제. 센서에서 멀어진 뒤 시스템 화면을 정상 사용 가능 |
| 프로세스 종료·리스너 연결 해제/재연결·재부팅 | 낡은 원문 알림이 남지 않음. 금지된 백그라운드 실행은 크래시/반복 재시도 없음 |

센서 가림과 화면 OFF/Activity onStop이 어떤 순서로 오는지 실제 One UI에서 특히 확인한다.
비 wake-up 센서만 있으면 CPU 수면 중 꺼내기/뒤집기 감지가 늦을 수 있다. 잠금 화면을 수동으로
켜서 복귀 가능함을 확인하고 자동 복귀 성공과 구분해서 기록한다.

## 앱 프레임 수와 물리 주사율

```bash
# 개인 알림/곡명을 출력하지 않는 앱 상태와 프레임 제출 카운터
adb shell dumpsys activity service dev.lutergs.sgaod/.service.AODService

# 논리 디스플레이 모드와 전력 상태 확인
adb shell dumpsys display
adb shell dumpsys power

# 한 번의 진단 캡처 (읽기 전용)
./scripts/capture-aod.sh /tmp/sgaod-diagnostics
```

앱 카운터 `submittedFrames`는 실제 Surface 버퍼 제출 횟수다. 두 시점의 차이로 비교한다.
정지 상태에서 시계는 분당 한 번 정도, 알림이 연속해서 와도 콘텐츠는 최대 초당 한 번이다.
검정 전환·Surface 생성/크기 변경의 초기 버퍼 제출은 예외로 기록한다.
암전/화면 꺼짐 상태에서는 초기 검정 전환 이후 카운터가 증가하지 않아야 한다.

`Display.refreshRate`, `dumpsys display`, 개발자 주사율 표시값은 논리 모드/합성 속도일 수 있다.
이를 물리 LTPO 패널의 실제 1Hz 증거로 단정하지 않는다. 패널 Hz 검증에는 해당 펌웨어가
노출하는 패널 진단·제조사 도구·적절한 하드웨어 측정이 필요할 수 있다.
1Hz 요청이 전달되었다는 것과 One UI가 실제 패널에 적용했다는 것을 따로 기록한다.

## 배터리 비교

동일한 온도·무선 연결·밝기·알림 빈도·초기 잔량에서 커버/내부 화면을 따로 비교한다.
USB 충전/ADB 연결을 끊고 충분히 긴 기간(예: 6–8시간)의 대기를 반복한다.
시스템 AOD, SG AOD 표시, SG AOD 가림, AOD 미사용을 서로 같은 조건으로 비교한다.
표시 제한(기본 30분)이 다른 그룹 결과를 왜곡하지 않도록 설정과 실제 표시 시간을 기록한다.

측정 전후 Batterystats/Perfetto를 필요에 따라 수집하되, 실시간 도구가 깨우는 비용을 분리한다.
검은 픽셀의 발광 감소만으로 시스템 AOD와 같은 소비전력이라고 판정하지 않는다.
